# FrameForge v1.6.0

**A quality and security release.** On top of the 1.5.1 P0/P1 hotfixes, this version completes the architecture items left for 1.6.0 by the review: the resource-arbiter deadlock, high-DPI dialogs, CPU load sampling, system file cache, NVAPI call safety, HDR/ACM detection and log privacy. All 23 picture presets were also recalibrated to the new parameter specification.

Download: `FrameForge.exe` (Windows 10/11, .NET Framework 4.8, single portable executable, administrator rights on first run).

## Picture filter

- **Colour-matrix orientation fixed**: matrices are built as column vectors internally and transposed once before being handed to the Win32 `MAGCOLOREFFECT` and GDI+ `ColorMatrix` APIs. Previously the preview and the live screen disagreed; they now match.
- **All 23 presets recalibrated**: saturation, contrast, brightness, white balance and shadow lift were re-tuned per the parameter specification, keeping indices 0–22 stable so saved preset references never shift. Fog boost now leans on a mild desaturation instead of extra contrast, and Night stays inside the warm safe zone.
- **Continuous white balance**: three fixed white points were replaced by a Planckian-locus interpolation driven by a Mired slider (±75), clamped to 2700–10000 K to avoid a green cast at the low end.
- **Safe ranges**: saturation is limited separately on the positive and negative halves (1.45 working, 1.65 total) and net black lift is capped at +0.055. Intensity is interpolated exactly once after composition, so chained interpolation no longer shifts colours.
- **HDR / auto colour management detection**: advanced colour state is read through `DisplayConfigGetDeviceInfo`; when it is on, the filter page states that Windows bypasses tone adjustments, and the state is re-probed after resolution, refresh-rate or display changes.

## Security

- Every system binary (powercfg, schtasks, shutdown, explorer and friends) is launched by absolute System32 path, and `SetDefaultDllDirectories` locks the DLL search path to System32 before any vendor DLL is resolved, closing the portable-folder side-loading hole.
- RTSS installers are always downloaded to a random directory and must match SHA-256; the old `%TEMP%` extraction is never reused. Update packages are re-hashed right before the installer launches, and PresentMon must carry a valid Intel signature.
- Boost journals are HMAC-signed (key stored under `%ProgramData%\FrameForge`), so a hand-edited journal can no longer trigger a restore. The optimization reader only accepts whitelisted registry keys and validates power-scheme GUIDs.
- Settings are sanitized on load: filter ranges, ICC paths (UNC, relative and overlong paths rejected), the ICC list length and overlay scale are all clamped, so a damaged config cannot break startup.
- NVAPI now only binds the well-defined `SetDVCLevel`. The `SetDVCLevelEx` variant (which passed a struct pointer where an integer level was expected) and the physical-GPU fallback that could target the wrong display on Optimus laptops are gone, and `NvAPI_Unload` is called on release.
- ICC parsing hardened: a 16 MB cap, offsets written to the correct channel slots, and curve/parametric-curve maths moved to `long` with 4-byte alignment.

## Reliability and performance

- **Resource arbiter reworked**: only state transitions happen under the lock; reading the old value, applying, restoring and owner callbacks all run outside it, removing the AB-BA deadlock between one-click and real-time boost. Ownership is persisted immediately when the holder changes, so crash recovery always restores the right engine's value.
- **Hybrid-core detection**: a CPU is treated as hybrid only when P-core and E-core frequencies differ by at least 10%, leaving homogeneous platforms on the previous decision. Intel laptops no longer mis-classify because of `EfficiencyClass` semantics.
- **CPU load sampling** now subtracts idle time from kernel time; idle cores no longer look half busy, and the core map and radar read the same corrected values.
- **Ideal processor**: threads are spread across available cores instead of being pinned to a single core, the main thread still lands on the sampled idle core, and the journal is written once per pass instead of once per thread.
- **Real-time boost cost**: the 5-second scan merges 13 name queries into one process enumeration; PIDs that fail elevation enter a 5-minute cooldown instead of writing two journal entries every tick; reverted actions are pruned once the journal passes 256 entries.
- **Memory trimming** only flushes the standby list for fullscreen games and shares a 30-second throttle with the real-time engine. Process trimming now starts from the largest working sets instead of the smallest tools.
- **System file cache** flushing now uses `SetSystemFileCacheSize(-1, -1, 0)`; the old zero-filled buffer was rejected by the kernel and always failed.
- **Interrupt tuning** only deletes the values it wrote, never the whole key, and devices without an explicit MSI flag are no longer assumed to be MSI-capable.
- **MPO toggle** fixed: enabling removes the override, disabling writes it back.
- **Shutdown path**: fullscreen filter, gamma LUT and backlight are dropped on logoff/shutdown and on window close before any system item is restored.
- **High-DPI dialogs** size themselves to the actual wrapped body text and the text area follows the window, so buttons no longer cover the message. Enter means Cancel on destructive confirmations (cleanup, restore, end process).

## Privacy and logs

- Logs are levelled (INFO / WARN / ERROR) and can be filtered with the `FRAMEFORGE_LOG_LEVEL` environment variable.
- Every entry is single-line (newlines become ` | `), user profile paths and user names are replaced with `%USERPROFILE%` / `%USER%`, and overlong lines are truncated.
- The main app and the watchdog serialise writes through a named mutex. The single-instance mutex moved from `Global\` to `Local\`, so multi-user sessions and Remote Desktop no longer block each other.

## UI

- The theme button now shows a sun in the light theme and a crescent moon in the dark theme, repainting immediately when the theme changes.

## Self-test

- Four new filter checks: neutral gray, row-vector export, night luminance range and CS2 shadow lift.
- A new advanced-colour probe line (off / supported / hdr / acm).
- A concurrent arbiter regression: two owners alternate acquiring the timer 60 times, verifying no deadlock and no reference-count leak.

## Known limitations

- Hybrid-core pinning, NVIDIA DVC, high-DPI layout and HDR on real hardware still need validation on the matching machines.
- With HDR/ACM enabled, Windows bypasses SDR tone adjustments; that is system behaviour, and the filter page only surfaces a hint.

## Upgrading

Replace the old `FrameForge.exe` with the new one; settings and boost journals stay compatible. Upgrading from v1.5.x keeps your existing configuration on first launch.
