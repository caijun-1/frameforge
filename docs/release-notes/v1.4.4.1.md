# FrameForge v1.4.4.1

## 中文

### 新增

- **AMD 显卡传感器**：以前显卡数据只走 NVIDIA 的 NVML，AMD 卡（RX 6600 / 6750 GRE / 7800 XT 等）一律读不到。现在接入 AMD 驱动自带的 ADL（`atiadlxx.dll`），温度、核心频率、显存频率、功耗都能正常显示。
- **显存通用兜底**：显存总容量从显示适配器注册表读取，已用量改用 WDDM 的「专用显存」计数器。即使厂商传感器不可用，NVIDIA / AMD / Intel 的显存占用仍然能显示。
- **健康检查更清楚**：显卡一行显示完整型号，并标注数据来源是 NVML（NVIDIA）还是 ADL（AMD）。

### 修复

- **「温度 / 频率 / 功耗 / 显存」全是 —**：NVML 只认 NVIDIA，非 N 卡之前直接放弃采集。现在按 NVML → ADL → 系统计数器的顺序逐层回退，能读到的都显示出来。
- **自检可定位问题**：`--selftest` 新增显卡温度检查，会明确写出是「没有厂商传感器」还是「驱动返回了空值」。

**完整校验值**：见附件 `FrameForge.exe.sha256`。

## English

### New

- **AMD GPU sensors**: GPU data used to come only from NVIDIA's NVML, so AMD cards (RX 6600 / 6750 GRE / 7800 XT …) showed nothing. The AMD driver's own ADL (`atiadlxx.dll`) is now used, so temperature, core clock, memory clock and power all display.
- **VRAM fallback for every vendor**: total VRAM is read from the display adapter registry and usage from the WDDM "Dedicated Usage" counter, so VRAM still shows up on NVIDIA, AMD and Intel GPUs even when the vendor sensor is unavailable.
- **Clearer health check**: the GPU row shows the full model and whether the data comes from NVML (NVIDIA) or ADL (AMD).

### Fixed

- **"Temperature / clock / power / VRAM" showing dashes**: NVML only supports NVIDIA, and the app previously gave up on everything else. It now falls back NVML → ADL → system counters and displays whatever is readable.
- **Self test pinpoints the cause**: `--selftest` now checks GPU temperature and reports whether no vendor sensor exists or the driver returned an empty value.

**Checksum**: see the attached `FrameForge.exe.sha256`.
