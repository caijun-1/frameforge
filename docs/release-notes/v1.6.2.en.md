# FrameForge 1.6.2

> Stability and readability release. It closes the edge cases from the leftover-defects review in resource arbitration, journal key handling, shutdown cleanup, the game database cache and the watchdog. The overlay now uses monospaced numbers and role-based colours, so readings no longer shift columns and FPS, 1% low, frame time and ambient info are easy to tell apart.

## Resources and transactions

- **SHARED acquires record their owner**: the arbiter now stores owner pointers for overlay users as well, so when the holder leaves first the remaining user immediately takes over the restore responsibility.
- **Reliable Busy cleanup**: the Busy flag around out-of-lock `powercfg` / `timeBeginPeriod` work is cleared in `try/finally` with `PulseAll`; waiters use a 30-second cap, and a stale flag is force-cleared and logged instead of blocking that resource forever.
- **Concurrency-safe journal key**: reading and creating the key is serialized in-process, published atomically through a temp file and verified by read-back. A concurrent instance never overwrites the key created by another; malformed key files are moved aside for inspection.
- **No silent quarantine of legitimate journals**: on an HMAC mismatch, if the key was created during this run (an old journal after a reinstall or `%ProgramData%\FrameForge` cleanup), the file is tagged `unverified` with an explicit warning and kept for review instead of being treated as forged.
- **Per-step shutdown isolation**: every step on close (timers, match record, settings, hotkeys, FPS, monitor, overlay, real-time boost) catches its own exception, and the one-click restore runs in `finally`, so a failure early in the chain can never leave the desktop boosted.
- **Thread-safe game database**: name/path/fallback caches are now concurrent dictionaries; the user database uses double-checked locking and publishes a fully built map, so the monitor thread and UI can query it at the same time.
- **Watchdog detects PID reuse**: the parent start time is passed to the watchdog. If the parent exits or its PID is reused, the watchdog will not wait on the wrong process, and stale transaction recovery still runs.
- **Explicit `--restore` exit codes**: 0 = all restored, 1 = unresolved items remain (conflict/failure), 2 = nothing to restore.

## Overlay readability

- **Monospaced numbers, fixed columns**: values use Consolas and each column is sized to “max characters × digit width”, so the OSD no longer jitters when FPS goes from 9 to 144.
- **Role-based colours**: FPS `#FF4FD8`, 1% low `#FFC7EE`, frame time `#4FD8E8`, device labels `#CED6E2`, clock/uptime `#9AA6B8` — shared by the live overlay, RTSS output and the settings preview.
- **Temperature thresholds**: GPU temperature turns amber at ≥70 °C and light red above 83 °C by default; both thresholds are configurable, and 0 disables that tier.
- **Consistent mini style**: now `144 FPS · 64°C`; the mixed-script `1%·5s` prefix is gone and 1% low is written as `1% 58`.
- **Segmented RTSS colours**: each label/value run uses its own role colour and closes with `<C>`, while the RTSS length cap still applies.
- **Two opt-in settings**:
  - `overlayBackdrop=subtle` — a very faint black plate under the text band (no rounded corners or border), off by default;
  - `overlayKeepPos=true` — keep the dragged position when switching style or corner.

## Fixes

- CPU/GPU usage no longer overlaps the average/max values on the report page (a layout regression in the 1.6.0 build).
- Self-test adds a zh/en string-key parity assertion (currently 640/640) and a corrupt-journal quarantine case: a journal with a bad checksum must be moved aside and never restored as a valid transaction.

## Upgrading

- Replace `FrameForge.exe`; settings and match history remain compatible.
- 1.6.0 journals can be reused. If `%ProgramData%\FrameForge\journal.key` was removed, old journals are reported as `unverified` in the log and are not restored automatically.
