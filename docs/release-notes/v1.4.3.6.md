# FrameForge v1.4.3.6

## 中文

### 新增

- **按 PCBoost 原理实装「理想处理器软引导」**：加速开始时、以及之后每 2 分钟，采样每个逻辑核的占用率，把游戏**主线程**的 `SetThreadIdealProcessor` 指向当前最空闲的核心。只给调度器一个"VIP 主场"提示，不修改亲和性掩码——游戏需要多核爆发时依然可以调用包括 CPU 0 在内的全部核心，不会浪费算力。
- **为什么会自然避开 CPU 0**：CPU 0 默认承担网卡、鼠标、显卡等硬件中断与大量系统底层服务，绝大多数时间占用率都不是最低的。按"选最闲"的规则挑选时它大概率不会被选中，从而与系统杂务核心错峰运行，而不是写死"禁用 CPU 0"。负载相同时优先编号非 0 的核心。
- **「游戏识别」说明**：硬性窗口样式排除、多信号评分、进程级 GPU 3D 证据、1.5 秒全量重扫与已确认进程记忆。

### 修复

- **漏检游戏、窗口一变就失效**：不再只盯前台窗口。每 1.5 秒枚举顶层窗口重新评分，前台进程一变立刻单独评估，并记住游戏窗口句柄；窗口化、改标题、换分辨率、读条、切菜单、回主菜单都不会再丢失状态。
- **误检为游戏**：识别不再"进程名命中就当游戏"。桌宠（Shimeji / Live2D 等）、虚拟键盘（触摸键盘 / Onboard）、加速器与监控悬浮窗（UU / 迅游 / BoosterX / 微星小飞机构件等）、启动器、编辑器与剪辑软件都会被提前排除；窗口化或从未见过的游戏改由"该进程 GPU 3D 引擎占用"这条硬证据识别，这也是游戏加加、微星小飞机的判断思路。
- **独占全屏下滤镜无效**：独占全屏会绕过 DWM，放大镜的颜色矩阵根本作用不到画面上。现在检测到独占全屏时自动改用显示器 gamma LUT，把颜色矩阵换算成逐通道曲线，亮度、对比度、色温、暗部提升继续生效；退出独占全屏后先还原原始 LUT，再切回放大镜，不会两层叠加。
- **滤镜预览"颜色太抽象"**：抽象色带换成合成的真实游戏场景（天空、远山、地面、人物剪影、准星与血条），直接套用当前颜色矩阵渲染，色温、暗部、肤色和 UI 是否变色一眼可见。
- **叠加层定位**：改为跟随游戏主窗口（优先 DWM 扩展边界）。窗口化时叠加层限制在游戏窗口内，铺满屏幕时贴合显示器边界；无论游戏是否在前台、在哪块屏幕，都能贴在游戏上面。

**完整校验值**：见附件 `FrameForge.exe.sha256`。

## English

### New

- **Ideal-processor soft steering, following the PCBoost model**: on boost and every 2 minutes thereafter, per-logical-core load is sampled and the game's **main thread** is pointed at the least busy core via `SetThreadIdealProcessor`. This is only a scheduler hint — affinity is never locked, so the game can still burst across every core including CPU 0.
- **Why it steers away from CPU 0 on its own**: CPU 0 carries most hardware interrupts (NIC, mouse, GPU) and system housekeeping, so it is rarely the idlest core. Picking "the least used" therefore naturally staggers the game away from the system core without hard-coding a CPU 0 ban. Ties prefer non-zero cores.
- **A new "Game detection" section** documenting the hard window-style exclusions, multi-signal scoring, per-process GPU 3D evidence, 1.5 s rescan and confirmed-process memory.

### Fixed

- **Missed detections and detection dropping after a window change**: the foreground window is no longer the only source. All top-level windows are re-scored every 1.5 s, foreground changes are evaluated immediately, and the game window handle is remembered — windowed mode, renamed titles, resolution changes, loading screens and alt-tabs keep the state.
- **False positives**: a process-name hit no longer means "game". Desktop pets, virtual keyboards, accelerator/monitor overlays, launchers, editors and NLEs are excluded up front; windowed or previously unseen games are recognised by the process's GPU 3D engine usage — the same signal used by GamePP and MSI Afterburner.
- **Filters not working in exclusive fullscreen**: exclusive fullscreen bypasses DWM, so the magnifier matrix never reaches the screen. FrameForge now falls back to the display gamma LUT, mapping the colour matrix onto per-channel curves so brightness, contrast, temperature and shadow lift keep working. The original LUT is restored before switching back to the magnifier, avoiding double-grading.
- **Abstract filter preview**: the swatch strip is replaced by a synthetic game frame (sky, mountains, ground, character silhouette, crosshair and HUD) rendered through the active colour matrix.
- **Overlay placement** now follows the game's main window (DWM extended bounds preferred): confined to the game window when windowed, snapped to the monitor when fullscreen.

**Checksum**: see the attached `FrameForge.exe.sha256`.
